## 핵심 구현 및 개발 포인트
- **Spring Security 기반 권한별 메뉴 및 접근 제어**: 백엔드에 Spring Security를 적용하여 로그인 사용자의 권한을 확인하고, 일반 사용자와 관리자 권한에 따라 접근 가능한 메뉴와 기능을 분리했습니다. 권한에 맞지 않는 화면 노출과 기능 접근을 제한하여 사용자 등급별로 필요한 기능만 제공되도록 구성했습니다.
- **관리자 전용 통합 대시보드 구현**: 관리자가 시스템 운영 현황을 한눈에 확인할 수 있도록 관리자 전용 대시보드를 구현했습니다. 오늘 방문자 수, 총 회원 수, 최근 10분 기준 접속자 집계를 상단에 배치하고, 최근 가입 회원 목록과 공방 승인 상태를 표 형태로 구성하여 관리자 업무의 조회 편의성과 운영 효율성을 높였습니다.
- **사용자 정보 관리를 위한 마이페이지 구현**: 사용자가 본인의 세부 정보와 권한 정보를 확인하고 수정할 수 있도록 마이페이지를 구현했습니다. 로그인 세션을 기반으로 사용자 정보를 화면에 전달하고, 개인정보 확인 및 수정 기능을 제공하여 계정 관리의 편의성을 개선했습니다.

## 트러블 슈팅
- **[현상]**  관리자 대시보드에서 최근 생성된 공방의 승인 상태 통계(승인/거절/대기)를 조회할 때, 특정 상태에 해당하는 공방 데이터가 없으면 그래프나 표에서 해당 항목이 누락되거나 빈 값으로 표시되는 문제가 발생했습니다.
- **[원인]** 통계 데이터를 상태별로 집계하는 과정에서 실제 데이터가 존재하는 상태만 결과에 포함되면서, 0건인 상태는 결과에서 누락되었습니다. 이로 인해 프론트엔드에서는 승인/거절/대기 중 일부 상태 값을 받지 못해 그래프와 표 표시가 불안정해졌습니다.
- **[해결]** 데이터가 없는 상태도 0건으로 명확히 표시되도록 백엔드 집계 로직과 응답 데이터를 수정했습니다. 승인/거절/대기 상태값을 기준으로 결과를 보정하고, 누락된 상태는 0으로 채워 반환하도록 처리했습니다. 이를 통해 대시보드 그래프와 표에서 모든 승인 상태가 항상 동일한 형식으로 표시되도록 개선했습니다.
- **[배운점]** 관리자 대시보드나 통계 기능에서는 데이터가 존재하는 경우뿐 아니라 0건인 경우도 중요한 정보라는 점을 배웠습니다. 통계 데이터를 설계할 때는 `Null`이나 누락된 결과를 그대로 화면에 전달하지 않고, 사용자가 해석 가능한 형태로 가공해야 데이터 신뢰성과 화면 안정성을 높일 수 있음을 깨달았습니다.
